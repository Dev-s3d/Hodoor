# دليل الأمان (Security Guide)

يشرح هذا الملف الآليات الأمنية المستخدمة داخل مشروع Hodoor لحماية البيانات والمستخدمين والعمليات المختلفة.

---

# مقدمة

الأمان جزء أساسي من أي نظام معلومات.

تم تصميم مشروع Hodoor بحيث يطبق مجموعة من الممارسات الأمنية التي تساعد على:

* حماية بيانات المستخدمين.
* حماية قاعدة البيانات.
* منع الوصول غير المصرح به.
* تقليل المخاطر الأمنية الشائعة.
* الحفاظ على استقرار النظام.

---

# الطبقات الأمنية داخل المشروع

يعتمد المشروع على عدة طبقات حماية تعمل معاً.

```text
المستخدم
    ↓
Validation
    ↓
Authentication
    ↓
Authorization
    ↓
Business Logic
    ↓
Database
```

---

# التحقق من الهوية (Authentication)

قبل السماح لأي مستخدم باستخدام النظام يجب التحقق من هويته.

يتم ذلك من خلال:

* اسم المستخدم.
* كلمة المرور.

---

# دورة تسجيل الدخول

```text
إدخال البيانات
      ↓
التحقق من المستخدم
      ↓
التحقق من كلمة المرور
      ↓
التحقق من حالة الحساب
      ↓
إنشاء Session
      ↓
الدخول للنظام
```

---

# الجلسات (Sessions)

يعتمد النظام على PHP Sessions لحفظ بيانات المستخدم الحالي.

---

## البيانات المخزنة داخل Session

أمثلة:

```php
$_SESSION['user_id']
$_SESSION['full_name']
$_SESSION['username']
$_SESSION['email']
$_SESSION['role']
```

---

# إعادة إنشاء معرف الجلسة

بعد نجاح تسجيل الدخول يتم تنفيذ:

```php
session_regenerate_id(true);
```

الهدف:

* منع Session Fixation.
* زيادة مستوى الأمان.

---

# الصلاحيات (Authorization)

بعد التحقق من هوية المستخدم يتم التحقق من صلاحياته.

---

## مستويات المستخدمين

```text
admin
supervisor
teacher
```

---

## التحقق من الصلاحيات

يتم استخدام:

```php
clsHelper::requireRole()
```

مثال:

```php
clsHelper::requireRole([
    'admin'
]);
```

---

# حماية الصفحات

كل صفحة حساسة يجب أن تحتوي على فحص صلاحيات.

مثال:

```php
require_once '../../includes/app.php';

clsHelper::requireRole([
    'admin'
]);
```

---

# منع الوصول المباشر

لا يسمح بتنفيذ بعض الصفحات مباشرة.

أمثلة:

```text
store.php
update.php
delete.php
```

يفضل التحقق من:

```php
$_SERVER['REQUEST_METHOD']
```

قبل تنفيذ أي عملية.

---

# التحقق من البيانات (Validation)

جميع البيانات المدخلة يجب التحقق منها قبل حفظها.

يتم ذلك بواسطة:

```text
clsValidator
```

---

## أمثلة

التحقق من الحقول المطلوبة:

```php
clsValidator::required($value);
```

---

التحقق من البريد الإلكتروني:

```php
clsValidator::email($email);
```

---

التحقق من الأرقام:

```php
clsValidator::integer($id);
```

---

التحقق من التواريخ:

```php
clsValidator::date($attendance_date);
```

---

# الحماية من SQL Injection

يستخدم المشروع:

```text
PDO Prepared Statements
```

في جميع الاستعلامات.

---

## مثال آمن

```php
$stmt = $conn->prepare(
    "SELECT * FROM students WHERE id = ?"
);

$stmt->execute([$id]);
```

---

## مثال غير آمن

```php
$sql = "SELECT * FROM students WHERE id = $id";
```

لا يجب استخدام هذه الطريقة.

---

# الحماية من XSS

لحماية صفحات النظام من XSS.

يتم استخدام:

```php
clsHelper::e()
```

---

## مثال

```php
<?= clsHelper::e($student_name); ?>
```

---

# حماية كلمات المرور

يجب عدم تخزين كلمات المرور كنص عادي.

---

## الطريقة الصحيحة

عند إنشاء المستخدم:

```php
$password = password_hash(
    $password,
    PASSWORD_DEFAULT
);
```

---

## التحقق من كلمة المرور

عند تسجيل الدخول:

```php
password_verify(
    $password,
    $hashedPassword
);
```

---

# ملاحظة مهمة

لا ينصح باستخدام:

```text
123456
admin
password
```

في البيئة الحقيقية.

---

# حماية قاعدة البيانات

يوصى بما يلي:

* استخدام مستخدم قاعدة بيانات خاص بالمشروع.
* عدم استخدام حساب Root في بيئة الإنتاج.
* استخدام كلمة مرور قوية.
* تقييد الصلاحيات قدر الإمكان.

---

# حماية ملفات الإعدادات

ملفات مثل:

```text
config/database.php
config/config.php
```

يجب عدم إتاحة الوصول المباشر إليها من المتصفح.

---

# حماية الأخطاء

في بيئة الإنتاج.

يفضل:

```php
display_errors = Off
```

وعدم عرض أخطاء PHP للمستخدم.

---

# حماية الجلسات

يفضل ضبط:

```php
session.cookie_httponly = On
```

و

```php
session.use_strict_mode = On
```

كلما أمكن.

---

# تسجيل العمليات الأمنية

يتم تسجيل العمليات المهمة داخل النظام.

أمثلة:

```text
تسجيل الدخول
تسجيل الخروج
إضافة مستخدم
تعديل مستخدم
حذف مستخدم
```

---

# مراقبة السجلات

يفضل مراجعة:

```text
modules/logs/
```

بشكل دوري لمتابعة:

* العمليات الحساسة.
* الأخطاء.
* الأنشطة غير المعتادة.

---

# النسخ الاحتياطي

يوصى بإنشاء نسخة احتياطية دورية من:

## قاعدة البيانات

```text
database/hodoor.sql
```

---

## ملفات المشروع

```text
assets/
classes/
config/
includes/
modules/
```

---

# أفضل الممارسات الأمنية

يجب الالتزام بالتالي:

* استخدام Validation.
* استخدام Prepared Statements.
* استخدام Password Hashing.
* استخدام Session Regeneration.
* التحقق من الصلاحيات في كل صفحة.
* استخدام clsHelper::e() عند عرض البيانات.
* تسجيل العمليات المهمة داخل Logs.
* عدم تخزين معلومات حساسة داخل GitHub.

---

# قائمة التحقق الأمنية

قبل إصدار أي نسخة جديدة:

* [ ] جميع الصفحات محمية.
* [ ] جميع النماذج تحتوي Validation.
* [ ] جميع الاستعلامات تستخدم PDO.
* [ ] كلمات المرور مشفرة.
* [ ] الجلسات تعمل بشكل صحيح.
* [ ] Logs تعمل بشكل صحيح.
* [ ] لا توجد بيانات حساسة داخل المستودع.

---

# الخلاصة

تم تصميم الطبقة الأمنية في Hodoor لتوفير مستوى جيد من الحماية للمستخدمين والبيانات من خلال:

* نظام تسجيل دخول آمن.
* نظام صلاحيات متعدد المستويات.
* حماية من SQL Injection.
* حماية من XSS.
* حماية الجلسات.
* تسجيل العمليات المهمة.

ويجب المحافظة على هذه المعايير عند تطوير أي جزء جديد من النظام.
